GenericAgent 智能体系统设计总览

基于 docs/ 下全部文档的综合整理 | 2026-05-09

概述

GenericAgent（GA）是一个通用型自进化LLM智能体系统，旨在实现本地计算环境内任务自动化。其核心设计理念是通过优化上下文信息密度来提升智能体性能，而非单纯扩展上下文长度。

核心定位

  • 模型无关：底层推理引擎（Claude、GPT、Gemini等）可替换，不影响执行逻辑、工具接口与内存架构
  • 统一智能体循环：每一步将全局记忆与当前任务规范结合形成执行上下文
  • 两种执行模式：交互模式（用户发起）与反射模式（环境触发）
  • 代码极简：核心代码库约3K行，核心智能体循环约百行

核心设计原则

原则描述
工具最小化将工具限制在必要的最小集合内，避免上下文膨胀；满足原子性与组合泛化
分层记忆仅保留小型常驻可见层（L1），深层记忆（L2~L4）按需访问
自我进化通过记录与更新信息环境实现跨任务经验整合，不修改基础模型
上下文压缩设定<3万标记紧缩预算，采用字符域启发式方法管理

交互模式

turn = 0;  handler.max_turns = max_turns
while turn < handler.max_turns:
    turn += 1
    response_gen = client.chat(messages=messages, tools=tools_schema)
    response = yield from response_gen
    if not response.tool_calls:
        tool_calls = [{"tool_name": "no_tool", "args": {}}]
    else:
        tool_calls = [{"tool_name": tc.function.name,
                       "args": json.loads(tc.function.arguments)}
                      for tc in response.tool_calls]
    for tc in tool_calls:
        outcome = handler.dispatch(tc["tool_name"], tc["args"], response)
        if outcome.should_exit: break
        if outcome.next_prompt:
            next_prompts.add(outcome.next_prompt)

调用流程

用户输入 ↓ LLM 收到 tools=TOOLS_SCHEMA ↓ LLM 决定调用哪个工具 → 返回 function_call ↓ agent_runner_loop() 解析 → 映射到同名 Python 函数 ↓ 执行结果送回 LLM → 继续推理或输出回复

创建新工具

✅ 可以：脚本级工具

通过 file_write + code_run 运行时创建。例：图床服务、OCR调试脚本。

❌ 不可以：动态注册FC工具

tools=[] 列表在对话开始时固定，中途不能追加。需要编辑 assets/tools_schema.json + 写Python实现，下轮会话生效。

策略

  • 反复使用的能力 → 写成 .py 模块放 memory/ 下
  • 一次性任务 → 直接用 code_run 内联代码
  • 持久化服务（如图床） → file_write 创建 → code_run 启动后台进程

DANGEROUS_PATTERNS = [

代码例证：上下文压缩（四阶段修剪）

ga.py 的 smart_format 函数实现了字符域启发式压缩——这是"上下文压缩"设计原则的具体实现：

def smart_format(data, max_str_len=100, omit_str=" ... "):
    """上下文截断与压缩：采用首尾策略对内容进行截断，限制单条消息长度。
    GA采用字符域启发式方法管理上下文预算，通过四阶段修剪机制控制长度：
    1. 工具输出截断：单工具输出超阈值时保留首尾，替换中间部分
    2. 标签级压缩：每五轮替换重复工作记忆块为占位符
    3. 消息清理：超预算时重新压缩并按先进先出删除旧消息
    4. 工作记忆锚定：每条新消息附加最新对话摘要、轮次编号与关键信息
    """
    if not isinstance(data, str): data = str(data)
    if len(data) < max_str_len + len(omit_str)*2: return data
    return f"{data[:max_str_len//2]}{omit_str}{data[-max_str_len//2:]}"

代码例证：工具分发机制

ga.py 的 BaseHandler.dispatch 方法将LLM返回的工具调用名映射到同名Python方法：

def dispatch(self, tool_name, args, response, index=0):
    method_name = f"do_{tool_name}"
    if hasattr(self, method_name):
        return (yield from getattr(self, method_name)(args, response))
    elif tool_name == "bad_json":
        return StepOutcome(None, next_prompt=args.get("msg", "bad_json"))
    else:
        return StepOutcome(None, next_prompt=f"未知工具 {tool_name}")

问题解决循环

接收任务 → 查记忆/读SOP → 探测环境状态 → 执行一步操作 → 验证结果 ├─ 成功 → 继续下一步 └─ 失败 → 升级策略 ├─ 1次：读错误日志 ├─ 2次：探测环境 └─ 3次：换方案或问用户 → 闭环确认（保存记忆/Git）

except FileNotFoundError:

    tgt = os.path.basename(path)
    # 自动扫描目录找相似文件
    cands = list(itertools.islice(
        (c for base in roots for c in _scan_files(base)), 2000))
    top = sorted([(difflib.SequenceMatcher(None, tgt.lower(),

    return msg

代码例证：强制 summary 机制

ga.py 中 turn_end_callback 函数的摘要提取逻辑，确保每一轮都生成 <summary> 标签：

def turn_end_callback(self, response, tool_calls, tool_results, turn, next_prompt, exit_reason):
    _c = re.sub(r"```.*?```|<thinking>.*?</thinking>", "", response.content, flags=re.DOTALL)
    rsumm = re.search(r"<summary>(.*?)</summary>", _c, re.DOTALL)
    if rsumm:
        summary = rsumm.group(1).strip()
    else:
        # 未输出summary时自动生成一个
        tc = tool_calls[0]
        summary = f"调用工具{tc['tool_name']}, args: {tc['args']}"
        if tc["tool_name"] == "no_tool":
            summary = "直接回答了用户问题"
        # 同时注入提示要求补充summary
        next_prompt += "\n\n\nUSER: <summary>呢？？？！\n\n"
    # 存入历史用于后续上下文注入
    self.history_info.append(f"[Agent] {summary}")

第1次失败 读错误日志，理解原因 — 被动反省

第2次失败 探测环境状态，获取更多上下文 — 主动反省

第3次失败 深度分析后换方案或问用户 — 根本性调整

核心约束：禁止无新信息的重复尝试。每次重试必须基于新的信息或不同策略。

多智能体系统

GenericAgent 支持四种多智能体协作模式，核心通讯基于文件系统异步IO协议 + 共享记忆。

主从模式（Master-Subagent）

主Agent通过文件系统与Subagent通讯：

文件方向用途
input.txt主→子任务目标与约束
context.json主→子绝对路径、交付物清单
output.txt子→主执行输出，[ROUND END]标记轮次
reply.txt主→子继续对话/追加指令
_intervene主→子纠偏指令
_keyinfo主→子注入working memory
_stop主→子终止信号

启动方式：

python agentmain.py --task my_task --input "任务描述" [--bg] [--llm_no N]

Map并行模式

适用独立同构子任务的批量处理：

  1. 主Agent准备N个独立输入文件
  2. 对每个文件启动一个 Subagent（--bg 后台）
  3. 等所有完成 → 读取各 output*.txt → 汇总结果

监察者模式（Supervisor-Worker）

监察者（Supervisor）— 只读、只判断、只干预，不下场干活 │ 读 output.txt（观察进度） │ 写 _intervene / _keyinfo（纠偏） ▼ 工作Agent（Worker） — 实际执行任务

监察者干预清单：跳步、细节遗漏、光说不做、断言无据、连续失败等。

共享记忆机制

所有Agent共享同一套记忆系统：L1 Insight、L2 Facts、L3 SOP/utils、keychain、文件系统。

多模型配置

通过 --llm_no N 参数为不同Subagent指定不同大模型：

# OCR 智能体 → 视觉模型 (llmclients[0])
python agentmain.py --task 截图分析 --input "..." --llm_no 0 --bg

# 文本智能体 → 纯文本模型 (llmclients[1])

def load_llm_sessions(self):
    mykeys, changed = reload_mykeys()
    llm_sessions = []
    for k, cfg in mykeys.items():
        if not any(x in k for x in ["api", "config", "cookie"]): continue
        if "native" in k and "claude" in k:
            llm_sessions += [NativeToolClient(NativeClaudeSession(cfg=cfg))]
        elif "native" in k and "oai" in k:
            llm_sessions += [NativeToolClient(NativeOAISession(cfg=cfg))]
        elif "claude" in k:
            llm_sessions += [ToolClient(ClaudeSession(cfg=cfg))]
        elif "oai" in k:
            llm_sessions += [ToolClient(LLMSession(cfg=cfg))]
        elif "mixin" in k:
            llm_sessions += [{"mixin_cfg": cfg}]
    return llm_sessions

代码例证：记忆蒸馏机制

ga.py 的 do_start_long_term_update 实现了"自我进化"——将任务经验蒸馏为长期记忆：

def do_start_long_term_update(self, args, response):
    prompt = """### [总结提炼经验]
提取最近一次任务中【事实验证成功且长期有效】的信息：
- 环境事实（路径/凭证/配置）→ file_patch 更新 L2，同步 L1
- 复杂任务经验（关键坑点/前置条件）→ L3 精简 SOP
**只能提取行动验证成功的信息**
**禁止**：临时变量、具体推理过程、未验证信息、通用常识
"""
    yield "[Info] Start distilling good memory for long-term storage.\n"
    path = "./memory/memory_management_sop.md"
    if os.path.exists(path):
        result = "自动读取L0内容：\n" + file_read(path, show_linenos=False)
    else:
        result = "Memory Management SOP not found. Do not update memory."
    return StepOutcome(result, next_prompt=prompt)
